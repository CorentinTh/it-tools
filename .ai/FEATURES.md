# Useful Features from Upstream Issues and Pull Requests

## Implementation status — 2026-07-18

- **DONE — first catalog feature:** NanoID Generator is delivered locally on the existing Web Crypto/rejection-sampling foundation with no upstream component code or new runtime generator dependency. It includes bounded batch/custom-alphabet controls, collision guidance, copy/download/clear, session-only privacy, unit/component/browser coverage, and a measured 23,225 B raw / 8,916 B gzip lazy closure.
- **DONE — second catalog feature:** the bounded local-only JSON Schema Validator is delivered for Draft 7, 2019-09, and 2020-12. Its route-owned worker accepts fragment-local references only, applies strict parse/node/depth/error/time limits including a combined schema/instance error-complexity gate, keeps content session-only, and returns source-aware sanitized errors. The final closure is 176,585 B raw / 53,355 B gzip, the worker is 161,471 B / 47,125 B, and the final 1 MiB production fixture measures 246 ms cold route / 205 ms ready / 0.0 ms longest task. Upstream issues #368/#801 were requirements research only; no upstream component code was copied.
- **DONE — third catalog feature:** local File Hash computes SHA-256/384/512 explicitly in one route-owned worker pass with fixed 4 MiB `Blob.slice()` windows, throttled progress, hard cancellation/replacement, strict exact-key envelopes, an 8 GiB policy ceiling, session-only file data, safe filename display, and no application whole-file buffer. The final closure is 56,994 B raw / 22,189 B gzip and its separately budgeted worker is 13,583 B / 6,298 B. Production Chromium hashes 256 MiB with all three algorithms in 9,999 ms, 0.0 ms longest observed Long Task, +1,922,904 B peak page heap, and +91,242,496 B peak browser-process RSS; online demand caching and a second offline hash pass. Issues #528 and PRs #535/#1141 were requirements research only; no upstream implementation code was copied.
- **IN PROGRESS — platform foundation:** all-tool Chromium route smoke, deterministic schema-v4 worker-aware route/bundle measurements, executable CI/release budgets, cross-route lifecycle probes, bounded Bcrypt/Regex/JSON/YAML task flows, readonly large-output preview, YAML pre-serialization allocation projection, and PWA cache-miss recovery are implemented. The shared terminate-and-replace task core is now proven by JSON/YAML and the new validator; common parser/depth/download policy plus remaining heavy-tool migrations stay open.
- **DONE — reusable randomness foundation:** secure unbiased browser randomness now serves Token, TOTP, UUID, and the delivered NanoID tool; the full caller inventory and UUID v1 seed repair are recorded in `.ai/RANDOMNESS.md`.
- **DONE — reusable prerequisite only:** Text Diff/editor worker ownership, privacy, and lifecycle are safe to reuse; the payload comparison is complete, and a worker-backed CodeMirror spike must pass the recorded gates before editor-heavy features are accepted.
- **NEXT FOCUS:** choose the next independent bounded feature while advancing only measured worker-transport residuals (envelope-first stale filtering and output-byte metadata trust) needed by a real consumer. Dependency/base-image vulnerability work remains a separate deferred track.

Current implementation evidence and the next feature-unblocking gates are in
`.ai/PROGRESS.md`. No upstream feature code has been merged or cherry-picked.

## Snapshot and selection method

All 710 issues and 997 pull requests in the snapshot dated 2026-07-12 were analyzed. The backlog contains many duplicates, translations, dependency-bot PRs, and ideas that would turn the product into a backend/SaaS. The list below retains features that fit the local product model: developer-first, client-side, self-hostable, offline where practical, and no transmission of user data by default.

A second-pass review on 2026-07-13 compared every item not already cited by the audit, then separately reviewed open PRs, open feature/bug issues, closed-unmerged proposals, and closed bug reports against the local source. The GitHub API still reported #1832 as the newest repository item, so the saved JSON snapshot remained complete.

An open PR is a source of requirements and test cases, not permission to cherry-pick it. Implementations must be adapted to the local branch.

## Defer or reject without a separate product decision

- The REST API/server layer in [PR #1819](https://github.com/CorentinTh/it-tools/pull/1819) changes the trust model, deployment, and operational complexity. It is a separate product, not a normal tool.
- The login/token gate in [PR #1574](https://github.com/CorentinTh/it-tools/pull/1574) cannot be secure in a static SPA alone; use an identity-aware proxy or backend if access control becomes a requirement.
- Persisting OTP secrets as proposed by [PR #1221](https://github.com/CorentinTh/it-tools/pull/1221) conflicts with the privacy policy. Explicit query import and non-persistent session state are acceptable alternatives.
- GeoIP, currency, public-IP, loan, and other API-backed ideas require a provider, SLA, privacy disclosure, and offline fallback; deterministic local tools should come first.
- Restoring all upstream translations is not planned: this fork is intentionally English-only. That requires a separate product decision rather than mechanical synchronization.
- Lifestyle calculators, random games, national-ID generators, and similar proposals are outside the developer/DevOps-first scope unless the product direction changes.
- Active network scanning/ping of arbitrary hosts is constrained by browser security and can create abuse/privacy risks; offline calculators and explicit DoH/HTTP tools are preferred.
- JavaScript obfuscation/deobfuscation, OCR, PDF mutation, HEIC/video processing, and other large WASM workloads should wait for worker, cancellation, memory, and bundle-budget infrastructure.
- Cloudflare/D1 favorites, temporary file sharing, and other hosted persistence proposals change the static/local trust boundary and require a separate backend product decision.
